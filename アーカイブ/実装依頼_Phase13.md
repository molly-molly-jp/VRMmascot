## タスク2：13-2 soundDelayMs UIチューニング

### 概要
登場演出A・BのsoundDelayMsを、config.jsonを直接編集せずに設定UIから調整・保存できるようにする。
モーションと音声のズレをアプリ再起動なしで試行錯誤できる。

### 要件

| # | 要件 | 詳細 |
|---|------|------|
| F13-2-1 | 配置 | 設定タブに、現在選択中のモデルのパターンA・パターンBそれぞれのsoundDelayMs表示欄を設ける |
| F13-2-2 | 操作 | ±50msのステッパーボタン（▲▼）で増減。0ms未満にはならない |
| F13-2-3 | 即時反映 | 値を変更した時点でその値が次の登場演出再生に使われる（再起動不要） |
| F13-2-4 | 保存 | 「保存」ボタンでconfig.jsonの該当モデルのsoundDelayMsに書き込む |
| F13-2-5 | モデル切替連動 | モデルを切り替えたとき、表示される値もそのモデルの設定値に更新される |
| F13-2-6 | パターンCは対象外 | パターンCのsoundDelayMsはconfig.json直接編集で対応する（全ペア共通値のため） |

### 完了条件
- 設定タブにパターンA・BそれぞれのsoundDelayMs表示と▲▼ボタンがある
- ▲▼ボタンで値が50ms単位で変化し、次の登場演出再生に即座に反映される
- 「保存」ボタンを押すとconfig.jsonに書き込まれる
- モデルを切り替えると表示値がそのモデルの設定値に変わる

### 完了したら
変更したファイルと変更箇所を報告して止まること。

## タスク3：13-3 カメラ＆ウィンドウ位置プリセット改善

### 概要
現状のカメラプリセットはカメラパラメータのみ保存しており、Electronウィンドウのスクリーン座標が含まれていない。
アバターの画面上の位置（左側定位置・右端・正面など）とカメラアングルをセットで保存・呼び出しできるようにする。

### 要件

| # | 要件 | 詳細 |
|---|------|------|
| F13-3-1 | ウィンドウ座標の保存 | プリセット保存時に、Electronの `getPosition()` でVRMウィンドウのスクリーン座標（x・y）を取得してconfig.jsonに追記する |
| F13-3-2 | ウィンドウ座標の復元 | プリセット呼び出し時に、カメラパラメータの復元と同時にElectronの `setPosition()` でウィンドウを指定座標に移動する |
| F13-3-3 | リセットはカメラのみ | リセットボタンはカメラパラメータのみdefaultに戻す。ウィンドウ位置はリセット対象に含めない |
| F13-3-4 | 登場演出との非連動 | プリセット呼び出しと登場演出（A/B/C）は連動しない。別々の操作として維持する |
| F13-3-5 | config.json構造変更 | presetsの各エントリにwindowX・windowYを追加する |
| F13-3-6 | 後方互換性 | windowX / windowY を持たない既存プリセットを呼び出した場合は、カメラパラメータのみ復元しウィンドウ位置は変更しない |

### config.jsonの構造（変更後）

```json
"camera": {
  "default": { "targetY": 1.4, "distance": 3.0, "rotX": 0.0, "rotY": 0.0 },
  "presets": [
    { "label": "プリセット1", "targetY": 1.4, "distance": 3.0, "rotX": 0.0, "rotY": 0.0, "windowX": 1600, "windowY": 200 },
    { "label": "プリセット2", "targetY": 0.9, "distance": 2.0, "rotX": 0.2, "rotY": 0.3, "windowX": 1800, "windowY": 600 },
    { "label": "プリセット3", "targetY": 1.6, "distance": 4.0, "rotX": -0.1, "rotY": 0.0, "windowX": 1600, "windowY": 200 }
  ]
}
```

### 完了条件
- プリセット保存時にウィンドウのスクリーン座標もconfig.jsonに保存される
- プリセット呼び出し時にウィンドウがその座標に移動する
- windowX/Yを持たない既存プリセットを呼び出してもエラーにならない
- リセットボタンはウィンドウ位置を変えない

### 完了したら
変更したファイルと変更箇所を報告して止まること。

## タスク5：13-5 ライティング調整UI

### 概要
ライティング設定をconfig.jsonを直接編集せずに設定UIから調整・保存できるようにする。
モデルごとに最適値が異なるため、モデルごとに保存する2段階設計を採用する。

### 設計方針（重要）
- グローバルデフォルト（config.jsonのトップレベル `lighting`）を維持する
- 各モデルに個別設定（model.lighting）があればそちらを優先する2段階設計
- モデルに個別設定がない場合はグローバルデフォルトの値を表示する

### 要件

| # | 要件 | 詳細 |
|---|------|------|
| F13-5-1 | 配置 | 設定タブに、現在選択中のモデルのライティング調整欄を設ける |
| F13-5-2 | 調整項目 | メインライトX（左右方向）・メインライト強度（intensity）・環境光強度（ambient）・shadingShiftFactor（影エリアの広さ）の4項目 |
| F13-5-3 | 操作方法 | 各項目をスライダーで調整する |
| F13-5-4 | スライダー範囲 | mainX: 0.0〜6.0 / mainIntensity: 0.0〜2.0 / ambient: 0.0〜1.0 / shadingShiftFactor: -1.0〜0.5 |
| F13-5-5 | 即時反映 | スライダーを動かした時点でVRMウィンドウのライティングに反映される（再起動不要） |
| F13-5-6 | 保存 | 「保存」ボタンでconfig.jsonの該当モデルのlightingに書き込む（モデルごと保存） |
| F13-5-7 | モデル切替連動 | モデルを切り替えたとき、そのモデルの個別設定があればその値を、なければグローバルデフォルト値を表示する |
| F13-5-8 | config.json構造変更 | 各モデルにlightingオブジェクトを追加できるようにする。グローバルのlightingはデフォルト値として維持する |

### config.jsonの構造（変更後）

```json
"lighting": {
  "ambient": { "intensity": 0.5 },
  "main": { "intensity": 1.0, "x": 3.0, "y": 2.0, "z": 1.0 },
  "shadow": { "enabled": false, "bias": -0.001 },
  "mtoon": { "shadingShiftFactor": -0.2 }
},
"models": [
  {
    "label": "Kyoko_Lwear",
    "path": "assets/groupA/Kyoko_Lwear.vrm",
    "lighting": {
      "ambient": { "intensity": 0.4 },
      "main": { "intensity": 1.2, "x": 4.0 },
      "mtoon": { "shadingShiftFactor": -0.3 }
    }
  }
]
```

### MToonの毎フレーム上書き設計（Phase 12-1からの継続）
`@pixiv/three-vrm` は毎フレーム `vrm.update()` を実行しマテリアルパラメータを上書きするため、
`vrm.update()` の直後に毎フレームMToonパラメータを強制上書きし続ける実装を維持すること。
モデル切り替え時は上書き対象の値を新しいモデルの設定値に切り替える。

### 完了条件
- 設定タブに4つのスライダーがある
- スライダーを動かすとVRMウィンドウのライティングがリアルタイムに変化する
- 「保存」ボタンを押すとconfig.jsonの該当モデルに書き込まれる
- モデルを切り替えると、そのモデルの個別設定またはグローバルデフォルト値がスライダーに反映される

### 完了したら
変更したファイルと変更箇所を報告して止まること。

## タスク6：13-6 未使用モデル設定クリーンアップ

### 概要
assetsフォルダからVRMファイルを削除しても、config.jsonにはモデルの設定が残り続ける。
VRChatアバター資産が多くモデルの出し入れが増える運用のため、手動で安全にクリーンアップできる機能を追加する。

### 設計方針
自動削除は採用しない。誤操作（一時的なファイル移動等）で調整済みの設定が消えるリスクがあるため、
手動で確認してから削除する方式にする。

### 要件

| # | 要件 | 詳細 |
|---|------|------|
| F13-6-1 | 配置 | 設定タブに「未使用モデル設定を削除」ボタンを設ける |
| F13-6-2 | 検出 | ボタン押下時に、config.jsonのmodels配列の各モデルのpathが実際にファイルとして存在するか確認する |
| F13-6-3 | 確認ダイアログ | ファイルが存在しないモデルの一覧を表示し、削除してよいか確認するダイアログを出す |
| F13-6-4 | 削除実行 | ユーザーが確認した場合のみ、該当モデルのconfig.json設定を削除してファイルに書き込む |
| F13-6-5 | 対象外 | ファイルが存在するモデルの設定は削除しない |
| F13-6-6 | 0件の場合 | 未使用モデルが0件の場合は「未使用のモデル設定はありません」と表示するだけ |

### 完了条件
- 設定タブに「未使用モデル設定を削除」ボタンがある
- ボタンを押すと存在しないVRMファイルのモデル一覧が表示される
- 確認後に削除するとconfig.jsonから該当エントリが消える
- 0件の場合はその旨のメッセージが表示される

### 完了したら
変更したファイルと変更箇所を報告して止まること。
