## 背景

現状のDOM取得方式はストリーミング完了後（デバウンス1500〜2000ms待機）に全文を一括送信するため、
AIの回答が長いほど読み上げ開始までのラグが大きくなり録画のテンポが悪くなる。
文単位で逐次送信することで最初の1文目の読み上げ開始を大幅に早める。
元の全文受信方式に戻せるよう、設定UIのON/OFFで切り替えできる設計にすること。

## タスク1：14-1 文単位逐次送信

### 概要

**変更対象ファイルはChrome拡張の `content_script.js` が主体。**
Electron側（main.js）のキュー管理・VOICEVOX送信は既存設計を流用する。

ストリーミング中のDOMの変化を監視し、句点で文が完結するたびにVOICEVOXへ逐次送信する。

### 要件

| # | 要件 | 詳細 |
|---|------|------|
| F14-1-1 | 変更対象ファイル | `content_script.js` の変更が主体。Electron側（main.js）のキュー管理・VOICEVOX送信は既存設計を流用する |
| F14-1-2 | 逐次送信 | ストリーミング中のDOMの変化を監視し、句点（。？！. ? !）で文が完結するたびにVOICEVOXへ送信する。ただし `1.` や `http://` など誤検知しやすいパターンは除外する |
| F14-1-3 | 既読追跡 | 送信済み文字数をカーソルとして保持し、前回カーソル以降の差分テキストのみを処理することで重複送信を防ぐ |
| F14-1-4 | デバウンス廃止 | 逐次送信モード時はデバウンスを廃止し、句点検知のみで送信する。全文受信モード時は既存のデバウンス（Gemini: 2000ms / ChatGPT・Grok: 1500ms）をそのまま使う |
| F14-1-5 | 不完全文の保留 | 句点が来ていない途中の文は保留し、次の句点が来たタイミングでまとめて送信する |
| F14-1-6 | ストリーミング終了時のフラッシュ | ストリーミング完了時に保留中の文（末尾に句点がない場合）も送信する |
| F14-1-7 | 中断時は破棄 | ストリーミングが途中で中断された場合は保留中の文を破棄する（送信しない） |
| F14-1-8 | GeminiのDOM書き換え | Geminiはストリーミング中にDOMを書き換えることがあるが、既送信分はキャンセルせず許容する |
| F14-1-9 | キュー維持 | 既存のCtrl+QやDOM取得のキュー管理と整合性を維持する |
| F14-1-10 | ON/OFF切り替え | config.jsonの `streamingTTS: true/false` で切り替え。設定タブのUIからON/OFFを変更できるようにする（再起動不要） |
| F14-1-11 | デフォルト | `streamingTTS` のデフォルトは `true`（逐次送信）とする |
| F14-1-12 | サービス共通 | Grok / Gemini / ChatGPT の3サービスすべてに対応する |

### config.jsonの構造

```json
"streamingTTS": true
```

### 変更対象ファイル

| ファイル | 変更内容 |
|---------|---------|
| `chrome-extension/content_script.js` | 文区切り検知・カーソル追跡・逐次送信ロジックの追加。デバウンス廃止（逐次モード時） |
| `main.js` | `streamingTTS` 設定の読み込み。Chrome拡張へのモード通知 |
| `renderer/control.html` / `ui.js` | 設定タブにstreamingTTSのON/OFFトグルを追加 |

### 完了条件
- AIのストリーミング中、句点ごとにVOICEVOXへ送信・読み上げが開始される
- 同じ文が重複して送信されない
- `streamingTTS: false` にすると従来の全文受信方式に戻る
- 設定タブのUIからON/OFFを切り替えられる（再起動不要）
- 既存のCtrl+Q・DOM取得停止ボタンは引き続き正常動作する
- Grok / Gemini / ChatGPT の3サービスで動作確認できる
